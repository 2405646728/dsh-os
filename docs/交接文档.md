## 6. 当前卡点：Hyper-V 装不上

**症状**：`Enable-WindowsOptionalFeature` 与 `DISM /Enable-Feature` 都报"操作成功完成"，功能状态显示 `Enabled`，但 `vmms.exe` / `vmcompute.exe` 不存在、`vmms` 服务也没注册，`Get-VM` 不可用。

**已收集的证据**：

| 检查项 | 结果 | 含义 |
|---|---|---|
| `Get-WindowsOptionalFeature` | `Microsoft-Hyper-V-All = Enabled` | 功能层认为已启用 |
| `bcdedit` | `hypervisorlaunchtype = Auto` | 引导配置没问题 |
| `C:\Windows\System32\vmms.exe` | 不存在 | **载荷没落盘** |
| `HKLM\SYSTEM\CurrentControlSet\Services\vmms` | 不存在 | 服务未注册 |
| `RebootPending(CBS)` | `True`（两次真重启后仍为 True） | 服务收尾阶段卡死 |
| CBS 日志 | `Last SuccessfulState: Pended，Status: 0x80070bc2` | 0x80070bc2 = 操作成功但需重启，循环 |
| `DISM /ScanHealth` | 未检测到组件存储损坏 | 组件库本身是好的 |
| 快速启动 | 已关闭（`HiberbootEnabled=0`） | 不是快速启动导致的假重启 |
| HypervisorPresent | `True` | 这是 VBS/内核隔离带来的，不等于 Hyper-V 可用 |

**结论**：Windows servicing 栈停在 Pended 阶段无法推进。这不是我们项目的问题，是那台机器 Windows 的状态问题。

**两条出路**：

| 方案 | 代价 | 适用 |
|---|---|---|
| A 修 Hyper-V | 需 1~2 次重启，成功不保证 | 想要接近原生的虚拟机性能 |
| B 改用 QEMU（TCG 软件模拟） | 装系统慢 5~10 倍（30~60 分钟），运行也慢 | 想今天就把系统跑起来验证功能 |

## 7. 下一步 SOP

### A. 修 Hyper-V（管理员 PowerShell）

```powershell
Dism /Online /Cleanup-Image /RestoreHealth
Dism /Online /Enable-Feature /FeatureName:Microsoft-Hyper-V-All /All /NoRestart
Dism /Online /Enable-Feature /FeatureName:VirtualMachinePlatform /All /NoRestart
Test-Path C:\Windows\System32\vmms.exe
```

最后一行输出 `True` → 重启后即可建机；输出 `False` → 走 B。
`RestoreHealth` 需要 10~20 分钟，必须跑到 100%。

### B. 改用 QEMU（管理员 PowerShell）

```powershell
winget install --id SoftwareFreedomConservancy.QEMU -e --accept-package-agreements --accept-source-agreements
& "C:\Program Files\qemu\qemu-system-x86_64.exe" --version
```

与 Hyper-V 路线的差别：QEMU 是纯用户态程序，不依赖 Windows 服务与内核模块，装完即用；但没有硬件加速。

### C. 虚拟机起来后的第一件事（三行验证）

```bash
systemctl --user status dsh 2>/dev/null || echo "还没装宿主"
loginctl show-user yg | grep Linger          # 应为 Linger=yes
ss -lntp | grep 8787                          # 宿主起来后应有监听
```

`Linger=yes` 是板块 2 的地基，装完必须立刻确认。

### D. 建机命令（Hyper-V 路线可用时）

```powershell
# 管理员 PowerShell，脚本已备好
powershell -ExecutionPolicy Bypass -File C:\Users\Lin\dsh-os-build\vm-create.ps1
```

脚本会：造 64MB CIDATA 种子盘 → 建 Gen2 VM（8 核 / 8GB / 120GB / 关 Secure Boot）→ 挂 ISO 与种子盘 → 开机。
约 8~12 分钟自动装完，账号 `yg` / `<见本地 build 文件夹>`，SSH 公钥已注入。

## 8. 关键决策与理由（防止以后翻案）

| 决策 | 理由 |
|---|---|
| 不用 Windows 服务 | 服务跑在 Session 0，没有 PTY、没有 GUI、没有通知，全废 |
| 整块 Samsung 盘给 Linux | 该盘上只有 431GB 的 E 盘（仅用约 3GB）和一个 500GB 的 APFS 旧分区，无 Windows 依赖 |
| 不加密磁盘 | 与"自动登录 + 开机即用"直接冲突 |
| 先 VM 后裸机 | 裸机装错了代价是重装系统，VM 装错了删掉重来 |
| 先 GNOME 后 sway | 先把网络、驱动、输入法调通，再换更轻的合成器；出问题能退回 |
| 用 Server 而非 Desktop 镜像 | VM 里没有显卡驱动问题，GNOME 层的价值不存在；Server 镜像小 2GB，autoinstall 原生支持 |
| 小模型不参与自动任务 | 1.5B 判断"这文件该干什么"错误率高，自动任务错一次要回滚 |
| 镜像模型走"先官方后固化" | DSH 现在一天一个样，一上来做 remaster 会被"改一行重出 5GB 镜像"拖死 |
| Dock 混合真程序 + 内部视图 | 全真程序会退化成启动器，全内部视图会逼着把浏览器也重写 |

## 10. 已知坑

1. **快速启动**：开着时"关机再开机"是休眠恢复，不算真重启——装双系统前必须关（已关）。
2. **APFS 残留**：Samsung 盘上 500GB 的未知分区其实是 APFS，整盘格掉前确认里面没要留的东西。
3. **BitLocker**：需要管理员权限才能查状态，装 Linux 前必须确认，否则挂载不了。
4. **这台机器没有默认管理员权限**：所有系统级操作都会弹 UAC，脚本要用 `Start-Process -Verb RunAs`。
5. **GitHub 账号名是数字**（2405646728），所以 Pages 地址是 `2405646728.github.io/dsh-os`；想要好看的域名得改账号名或挂自定义域名。
6. **GitHub 会拦无头浏览器**：截图仓库页会返回 unicorn 拦截页，用 markdown 渲染 API 验证才可靠。
7. **图片生成不可用**：当前没有配 Google Gemini key，`generate_image` 会直接报错。
8. **中文路径**：仓库里带中文文件名（`docs/DSH-系统化方向.md`），链接会被自动百分号编码，正常。

## 12. 重装后怎么让"我"回来

**前提说清楚：新装的 DSH 是一个全新会话，它不会记得我们聊过什么。** 上下文靠文档接，不靠记忆。

### 最小动作

把 `00-重新接入指令.md` 里那段话整段发给新会话。它会让新会话读本文档与脑图，然后回答三件事：项目在做什么、卡在哪、身份与约定是什么。答对了就说明接上了。

### 想连语气和边界一起恢复

人设是独立的一层：

```powershell
copy "C:\Users\Lin\dsh-handover-20261110\config\prompt-inject.md" "C:\Users\Lin\.dsh\prompt-inject.md"
```

放回去之后，人设对每个新会话自动生效，不用每次交代。

### 为什么给文档就够

本文档写死了四类东西，不依赖任何记忆：**结论**（11 个板块定了什么、为什么）、**状态**（卡在哪、证据是什么）、**路径**（下一步的完整命令）、**位置**（文件在哪、恢复时复制到哪）。任何会话拿到它都能从这里继续。
